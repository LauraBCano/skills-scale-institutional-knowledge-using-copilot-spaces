# Scale Institutional Knowledge Using Copilot Spaces

A GitHub Skills exercise repository that demonstrates how to use GitHub Copilot Spaces to document, organize, and scale institutional knowledge across teams.

## 📋 Project Overview

This repository contains:

- **OctoAcme Project Management Documentation**: A comprehensive set of process guides for managing projects from initiation through retrospective
- **Copilot Spaces Integration**: Examples of how to leverage Copilot Spaces to make institutional knowledge discoverable and accessible
- **Best Practices**: Templates and patterns for documenting processes that help teams onboard faster and maintain consistency

## 🚀 Getting Started

### For New Team Members

1. **Start here**: Read the [docs/README.md](./docs/) for an overview of the OctoAcme project management approach
2. **Understand roles**: Review [Roles and Personas](./docs/octoacme-roles-and-personas.md)
3. **Learn the lifecycle**: Explore the docs in order:
   - [Project Initiation](./docs/octoacme-project-initiation.md)
   - [Project Planning](./docs/octoacme-project-planning.md)
   - [Execution & Tracking](./docs/octoacme-execution-and-tracking.md)
   - [Release & Deployment](./docs/octoacme-release-and-deployment.md)
   - [Retrospectives & Continuous Improvement](./docs/octoacme-retrospective-and-continuous-improvement.md)

### For Existing Team Members

- **Reference the process docs** in the [docs/](./docs/) folder for specific guidance on any project phase
- **Use Copilot Spaces** to ask questions about project processes and get relevant documentation context
- **Contribute improvements** via pull requests using the [process docs issue template](./.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml)

## 💡 Using This Repository with Copilot Spaces

This repository is designed to work with **GitHub Copilot Spaces**, which helps teams:

- **Discover knowledge**: Ask Copilot about project processes and get relevant documentation automatically
- **Stay in context**: Reference process docs without leaving your IDE or PR
- **Onboard faster**: New team members can quickly find answers to common questions
- **Scale practices**: Centralize institutional knowledge that scales with your team

### Example Copilot Space Questions

- _"How do I start a new project?"_
- _"What's the deployment checklist?"_
- _"Who are the key stakeholders in project execution?"_
- _"What are the acceptance criteria for a release?"_

## 🔄 Contributing

To suggest updates or add new content to the project management documentation:

1. **Open an issue** using the [Add/Update Content](/.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml) template
2. **Propose changes** that align with OctoAcme's project management principles
3. **Get stakeholder review** for significant process changes
4. **Submit a pull request** with your updates

### Acceptance Criteria for Updates

- Content aligns with existing process docs
- Update improves clarity or closes a documented gap
- Proposed content has been reviewed with stakeholders (if needed)

## 📚 Key Principles

OctoAcme's project management approach is built on:

- **Iterative delivery**: Breaking work into small, testable increments
- **Clear roles**: Defined responsibilities and accountabilities
- **Risk & quality focus**: Proactive management and high standards
- **Transparency**: Documented decisions and continuous improvement
